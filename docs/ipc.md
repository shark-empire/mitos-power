# mitos-power IPC / API reference

This is the complete reference for every endpoint mitos-power exposes:
every method other components can call, every event they can subscribe to,
the permission model, and the exact wire format. If you're implementing an
IPC client for mitos-gui, mitos-session, mitos-settings, mitos-terminal, or
any other application, this document plus `src/ipc/*.rs` is the ground truth
(the Rust types in `src/ipc/protocol.rs` and `src/ipc/messages.rs` are
authoritative -- this document is generated by hand from them, so if the two
ever disagree, trust the code and file a doc bug).

A ready-to-use Rust client (`mitos_power::ipc::IpcClient`) is exported by the
`mitos-power` library crate -- if your component is also written in Rust,
you can depend on that crate directly instead of re-implementing the wire
protocol from this document.

## Transport

| | |
|---|---|
| Socket | `/run/mitos/power.sock` (configurable: `power.toml` -> `general.socket_path`) |
| Kind | Unix domain socket, `SOCK_STREAM` |
| Framing | Newline-delimited JSON (NDJSON) -- one complete JSON object per line |
| Permissions | mode `0660`, group `power` by default (`general.socket_group`) |
| Encoding | UTF-8 |

Each line sent in either direction is one complete, self-contained JSON
object. There is no length prefix and no multi-line message -- every
message fits on one line and is newline-terminated.

## Wire format

### Client -> server: `ClientMessage`

Every message from a client is one of three shapes, distinguished by the
`kind` field:

**Request** -- call a method:
```json
{"kind": "request", "id": "a1b2c3", "method": "GetBattery", "params": {"id": "BAT0"}}
```
- `id`: any string you choose; echoed back in the response so you can
  correlate replies to requests on a connection with multiple in flight.
- `method`: one of the names in the [method reference](#method-reference).
- `params`: object matching that method's params (see the reference below).
  **Methods with no required params accept `params` being omitted entirely,
  `null`, or `{}` interchangeably** -- the server ignores it either way.
  Methods with any required field need a real object; sending `null` there
  returns `INVALID_PARAMS`.

**Subscribe** -- start receiving events on this connection:
```json
{"kind": "subscribe", "events": ["BatteryChanged", "ACChanged"]}
```
Use `"*"` as the sole entry to subscribe to every event.

**Unsubscribe**:
```json
{"kind": "unsubscribe", "events": ["BatteryChanged"]}
```

### Server -> client: `ServerMessage`

**Response** -- reply to exactly one request, correlated by `id`:
```json
{"kind": "response", "id": "a1b2c3", "ok": true, "result": {"...": "..."}}
```
```json
{"kind": "response", "id": "a1b2c3", "ok": false, "error": {"code": "NOT_FOUND", "message": "battery 'BAT9' not found"}}
```
`result` is present only when `ok` is `true`; `error` only when `ok` is
`false`.

**Event** -- unsolicited push to every connection subscribed to it:
```json
{"kind": "event", "event": "BatteryChanged", "data": {"...": "..."}, "timestamp": "2026-09-24T14:03:11Z"}
```

## Connecting

A single connection can send requests and receive subscribed events
interleaved on the same socket. In practice, most clients want two
connections: one for request/response (send a request, read exactly the
matching response, repeat), and a second dedicated purely to
`subscribe` + reading a continuous event stream. That's what
`mitos_power::ipc::IpcClient` is built around: `call()` reads lines until it
finds the response matching its own `id`, silently skipping any event lines
it encounters along the way -- fine for a connection used only for
request/response, not a substitute for a real event-reading loop.

## Permissions

Every request is checked against the connecting process's Unix credentials
(`SO_PEERCRED`) before it runs. Three tiers:

| Tier | Who | 
|---|---|
| **Public** | Any process that can open the socket at all |
| **Session** | Same as Public today (no further restriction yet -- see audit.md; intended to eventually mean "the active seat's session user") |
| **Privileged** | `uid == 0`, or a member of `security.privileged_group` (default `power`) |

A method not in any known list (typo, or a future/removed method) defaults
to **Privileged** -- unrecognized method names fail closed, not open.

## Method reference

`R` column: params required to include a real (non-null) object; a dash
means params can be omitted/`null`/`{}` interchangeably.

### Public

| Method | R | Params | Result |
|---|---|---|---|
| `Ping` | – | | `{"pong": true}` |
| `GetVersion` | – | | `{"version": "0.1.0"}` |
| `GetPowerState` | – | | [`PowerStateSnapshot`](#powerstatesnapshot) |
| `GetBattery` | – | `{"id"?: string}` (omit for the first/primary battery) | [`BatteryInfo`](#batteryinfo) |
| `GetBatteries` | – | | array of [`BatteryInfo`](#batteryinfo) |
| `GetAcState` | – | | `"online"` \| `"offline"` (bare string) |
| `GetProfile` | – | | [`ProfileInfo`](#profileinfo) |
| `ListProfiles` | – | | array of [`ProfileInfo`](#profileinfo) |
| `GetBrightness` | – | | `{"percent": 0-100}` |
| `GetThermalState` | – | | [`ThermalSummary`](#thermalsummary) |
| `GetThermalZones` | – | | array of [`ThermalZoneInfo`](#thermalzoneinfo) |
| `ListInhibitors` | – | | array of [`InhibitorInfo`](#inhibitorinfo) |
| `GetLidState` | – | | `{"closed": bool \| null}` (`null` = no lid switch on this machine) |
| `GetIdleState` | – | | `{"idle_seconds": u64, "tier": "awake"\|"dim"\|"off"}` |
| `AcquireInhibitor` | **yes** | `{"who": string, "why": string, "what": "suspend"\|"shutdown"\|"idle"\|"all", "mode"?: "block"\|"delay"}` (`mode` defaults to `"block"`) | `{"id": "<uuid>"}` |
| `ReleaseInhibitor` | **yes** | `{"id": "<uuid>"}` | `{}` |
| `ReportActivity` | – | | `{}` (resets the idle timer; called by mitos-gui/mitos-session on real user input) |

### Session

| Method | R | Params | Result |
|---|---|---|---|
| `SetProfile` | **yes** | `{"name": string}` | `{}` |
| `SetBrightness` | **yes** | `{"percent": 0-100}` | `{}` |
| `SetIdleTimeout` | **yes** | `{"secs": u64}` | `{}` |

### Privileged

| Method | R | Params | Result |
|---|---|---|---|
| `Suspend` | – | | `{}` (does not return until the machine has resumed) |
| `Hibernate` | – | | `{}` |
| `HybridSleep` | – | | `{}` |
| `SuspendThenHibernate` | – | | `{}` |
| `Shutdown` | – | `{"force"?: bool}` (default `false`; `true` skips the Shutdown-inhibitor check) | `{}` (does not return -- the machine powers off) |
| `Reboot` | – | `{"force"?: bool}` | `{}` (does not return) |
| `Poweroff` | – | | `{}` (does not return; equivalent to `Shutdown` with `force: true`) |
| `Logout` | – | | `{}` (**currently a no-op** -- mitos-session integration not implemented, see audit.md) |
| `ScheduleShutdown` | **yes** | `{"at": "<RFC3339 timestamp>", "reboot"?: bool}` | `{"id": "<uuid>"}` |
| `CancelScheduledOperation` | **yes** | `{"id": "<uuid>"}` | `{}` |

### Result type shapes

##### `PowerStateSnapshot`
```json
{
  "on_ac": true,
  "batteries": [ /* BatteryInfo[] */ ],
  "overall_percentage": 76.0,
  "profile": {"kind": "balanced"},
  "lid_closed": false,
  "display_brightness_percent": 70,
  "thermal_level": "nominal",
  "active_inhibitors": 0,
  "idle_seconds": 12
}
```
`profile` is `{"kind": "performance"|"balanced"|"power_saver"}` for a
built-in, or `{"kind": "custom", "name": "studio"}` for a custom one.

##### `BatteryInfo`
```json
{
  "id": "BAT0", "present": true, "percentage": 76.3, "status": "discharging",
  "energy_now_wh": 34.2, "energy_full_wh": 45.0, "power_now_w": 8.1,
  "voltage_now_v": 11.6, "current_now_a": 0.7, "temperature_c": 31.4,
  "cycle_count": 214, "health_percent": 91.2, "health_label": "excellent",
  "time_to_empty_secs": 15200, "time_to_full_secs": null,
  "technology": "Li-ion", "manufacturer": "SMP", "model_name": "L20D3PG0"
}
```
Any field the hardware doesn't expose is `null` rather than omitted, so
clients can rely on every key being present.

##### `ProfileInfo`
```json
{
  "name": "balanced", "kind": {"kind": "balanced"}, "is_custom": false,
  "settings": {
    "cpu_governor": "schedutil", "cpu_boost": true,
    "display_timeout_secs": 600, "display_max_brightness_percent": 100,
    "background_throttle": false,
    "description": "Normal CPU scaling, normal display timeout, normal background policy"
  }
}
```

##### `ThermalSummary`
```json
{"level": "nominal", "highest_temp_c": 54.2, "warning_temp_c": 80.0, "critical_temp_c": 95.0}
```

##### `ThermalZoneInfo`
```json
{"id": "thermal_zone0", "zone_type": "x86_pkg_temp", "temperature_c": 54.2, "trip_warning_c": 90.0, "trip_critical_c": 105.0}
```

##### `InhibitorInfo`
```json
{"id": "<uuid>", "who": "mitos-video", "why": "Movie is playing", "what": "idle", "mode": "block", "created_at": "2026-09-24T14:00:00Z"}
```

## Event reference

Subscribe with `{"kind":"subscribe","events":[...]}`; every event arrives as
`{"kind":"event","event":"<name>","data":{...},"timestamp":"..."}`.

| Event | `data` | Emitted when |
|---|---|---|
| `BatteryChanged` | array of [`BatteryInfo`](#batteryinfo) (all batteries) | Any battery's reported percentage changes |
| `ChargingChanged` | array of [`BatteryInfo`](#batteryinfo) | Any battery's charging status changes |
| `ACChanged` | `{"online": bool}` | AC adapter plugged or unplugged |
| `ThermalWarning` | [`ThermalSummary`](#thermalsummary) | Thermal level transitions into Warning |
| `ThermalCritical` | [`ThermalSummary`](#thermalsummary) | Thermal level transitions into Critical (an emergency shutdown is already underway by the time this is sent) |
| `LidChanged` | `{"closed": bool}` | Lid opened or closed (polled, not instant -- see audit.md) |
| `PowerButtonPressed` | `{"action": "Ignore"\|"Lock"\|"Suspend"\|"Hibernate"\|"Shutdown"\|"Reboot"}` | A classified power-button press (**not currently reachable** -- no live event source wired up yet, see audit.md) |
| `SuspendStarted` | `{"requester": string, "method": "suspend"\|"hibernate"\|"hybrid_sleep"\|"suspend_then_hibernate"}` | Right before the kernel sleep call |
| `SuspendFinished` | `{"method": string}` | Right after the kernel sleep call returns (i.e. hardware has woken) |
| `ResumeStarted` | `{}` | Post-resume restoration begins |
| `ResumeFinished` | `{}` | Post-resume restoration complete |
| `ProfileChanged` | [`ProfileInfo`](#profileinfo) | Active profile switched |
| `BrightnessChanged` | `{"percent": 0-100}` | Brightness changed |
| `InhibitorAcquired` | `{"id": "<uuid>", "who": string, "why": string, "what": string}` | A new inhibitor was acquired |
| `InhibitorReleased` | `{"id": "<uuid>"}` | An inhibitor was released (explicitly, or automatically on client disconnect) |
| `IdleStateChanged` | `{"idle_seconds": u64, "tier": "awake"\|"dim"\|"off"}` | Idle tier transitions (including back to `awake` on activity) |
| `ShutdownScheduled` | `{"id": "<uuid>", "at": "<RFC3339>", "reboot": bool}` | `ScheduleShutdown` succeeded |
| `ShutdownCancelled` | `{"id": "<uuid>"}` | `CancelScheduledOperation` succeeded |

## Error codes

```json
{"code": "NOT_FOUND", "message": "battery 'BAT9' not found"}
```

| Code | Meaning |
|---|---|
| `INVALID_REQUEST` | The line sent wasn't valid JSON, or didn't match any `ClientMessage` shape |
| `INVALID_PARAMS` | `params` didn't match the method's expected shape |
| `UNKNOWN_METHOD` | `method` isn't one of the names in this document |
| `PERMISSION_DENIED` | Caller's uid/gid doesn't meet the method's [permission tier](#permissions) |
| `NOT_FOUND` | Referenced battery/profile/inhibitor/scheduled-operation id doesn't exist |
| `INHIBITED` | Blocked by one or more held inhibitors; `message` lists them as `"who: why"` |
| `INVALID_STATE` | Requested action doesn't make sense in the current state |
| `UNSUPPORTED` | This hardware/kernel doesn't support the requested operation (e.g. `Hibernate` with no swap) |
| `HARDWARE_ERROR` | A sysfs read/write or syscall failed |
| `CONFIG_ERROR` | (Only at daemon startup / SIGHUP reload, never from a request) |
| `IO_ERROR` | Underlying I/O failure not covered by a more specific code |
| `INTERNAL_ERROR` | Anything else |

## Who calls what

| Component | Typical usage |
|---|---|
| **mitos-gui** | Subscribes to almost everything for a status-bar power indicator; calls `SetBrightness`/`SetProfile` from quick-settings; owns actual screen blanking/DPMS and color temperature, driven by `IdleStateChanged` (mitos-power tracks *intended* display state but doesn't own the compositor -- see `docs/architecture.md`) |
| **mitos-session** | Subscribes to `SuspendStarted`/`ResumeFinished` to lock/unlock the session around sleep; is the intended target of `Logout` (not yet implemented -- see audit.md); calls `ReportActivity` on real input events |
| **mitos-settings** | `ListProfiles`/`SetProfile`, `ListInhibitors` (troubleshooting UI), reads `sleep.toml`/`display.toml`/etc. directly for the settings panel itself (not through mitos-power's IPC -- config *files* aren't served over IPC, only current *state*) |
| **mitos-terminal** | Nothing special; same public surface as any other client |
| **mitos-powerctl** | The reference CLI client for this whole API -- see `bin/mitos-powerctl.rs` for a complete worked example of every method |
| **Applications** | `AcquireInhibitor`/`ReleaseInhibitor` (media players, installers, backup tools), read-only `Get*` calls for a battery indicator |

## Worked example

Using `mitos_power::ipc::IpcClient` (see `bin/mitos-powerctl.rs` for the full
version):

```rust
let mut client = IpcClient::connect(Path::new("/run/mitos/power.sock")).await?;

let battery = client.call("GetBattery", serde_json::json!({})).await?;
println!("{}%", battery["percentage"]);

client.call("AcquireInhibitor", serde_json::json!({
    "who": "my-app", "why": "Exporting a video", "what": "idle"
})).await?;
```

Raw NDJSON equivalent of the first call, if you're implementing a client in
another language:
```
--> {"kind":"request","id":"1","method":"GetBattery","params":{}}
<-- {"kind":"response","id":"1","ok":true,"result":{"id":"BAT0","percentage":76.3,...}}
```
